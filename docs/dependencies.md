# Dependencies

Every direct third-party dependency of the workspace: which crate uses it, why it is here, what else was considered, and what it costs. The policy it follows is in [architecture/01-workspace.md](architecture/01-workspace.md) ("Third-party dependency policy"), and the measurements behind the choices are in [measurements/dependency-costs.md](measurements/dependency-costs.md).

**No new dependency without a row here.** `cargo xtask rules` compares the table below with the manifests and fails when they disagree: a dependency with no row, a row with no dependency, or a row that names the wrong crates. It is part of the blocking checks.

## Adding a dependency

1. Check that it passes the policy: it earns its place over the standard library, it needs no build tool beyond the platform's compiler, and its licence is on the allow-list in [testing-and-ci.md](testing-and-ci.md).
2. Add it to `[workspace.dependencies]` in the root `Cargo.toml` with `default-features = false`, and opt in to the features that are used.
3. Reference it from the one crate that owns it with `name.workspace = true`.
4. Add a row to the table below. Measure the cost the way [measurements/dependency-costs.md](measurements/dependency-costs.md) describes, or cite the figure from that page.
5. Run `cargo xtask check`. The lockfile changes with the manifest and is committed with it.

## Considered and not added

Dependencies that a step weighed and decided against, with the measurement, so that the question is not asked again without new facts.

### A shell parser, for command analysis (step 12)

The permission engine analyses shell commands ([architecture/06-permissions-and-sandbox.md](architecture/06-permissions-and-sandbox.md), "Shell command analysis"). The page left the choice to step 12: a pure-Rust parser crate or a hand-written tokenizer. **A hand-written allow-list tokenizer was chosen** ([decision 0031](decisions/0031-command-analysis-by-allow-list.md)), one for POSIX shells and one for PowerShell, in `cortex-policy`. No crate was added.

Measured on 2026-11-13 on 4 desktop cores, by the method of [measurements/dependency-costs.md](measurements/dependency-costs.md): one small program per candidate that reads a command line and prints its simple commands, built clean in the dev profile and in release (thin LTO, one codegen unit, stripped). No other session's build was running.

| Candidate | Dev build | Release build | Size added | Packages | Licence, upkeep |
|---|---|---|---|---|---|
| Empty program | 0.4 s | 1.2 s | 0 (305 KB) | 1 | |
| Hand-written tokenizer (the 310-line prototype) | 0.2 s | 1.3 s | 27 KB | 1 | Ours |
| `brush-parser` 0.4.0 | 6.7 s | 10.9 s | 365 KB | 75 | MIT; active (released May 2026) |
| `conch-parser` 0.1.1 | 0.5 s | 3.0 s | 226 KB | 3 | MIT or Apache-2.0; last release 2019 |
| `yash-syntax` 0.25.0 | not measured | | | | GPL-3.0-or-later: not on the licence list |

Why not a parser crate, in the order that mattered:

- **A full parser fails open.** It returns a tree for everything the shell accepts, and the engine would then have to remember to refuse each construct. Forty-three tricky lines were put to all three. With `brush-parser`, `{a,b}` and `{1..3}` come back as plain text (brace expansion is a third parser call), `ls &`, `! ls` and `time ls` come back as a plain `ls` unless three separate flags are checked, and `ls =cat`, which zsh expands to a program's path, is plain text. Each is a place where one forgotten check means "read-only" for something that is not. An allow-list refuses a character it does not list, so a construct nobody thought of is refused by construction.
- **It would not remove the word check.** `brush-parser` keeps each word as raw text; expansions, globs and braces are found by separate calls. The allow-list would still be written, on top of 75 packages (`insta`, `cached`, `bon`, `peg` and `tracing` are normal dependencies of it).
- **One grammar does not fit the shells the tool starts.** The shell tool runs bash, `sh` (dash on Debian and Ubuntu), or whatever `shell.program` names. A bash parser models bash. The subset the tokenizer accepts means the same in bash, dash, zsh and ksh, and that is tested against bash and dash on every run.
- `conch-parser` is abandoned and misreads bash's forms: `echo hi &> out` as a background job and a redirection; `<<<` and `|&` as parse errors.

The cost of the choice is upkeep of about 700 lines of tokenizers and their tests, and a subset narrower than a parser's: a line with `$`, a back-tick or a backslash outside quotes is asked about where a parser could have read it.
