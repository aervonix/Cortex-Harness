# 0011: Command-line parsing with lexopt and hand-written help

- **Status:** Accepted
- **Date:** 2026-11-12

## Context

The `cortex` binary has a modest command line: a few global flags, a handful of subcommands (`serve`, `attach`, `auth`, `config`, `sessions`, `permissions`, `project`, `stats`, `ext`, `mcp`, `debug`), and a prompt argument. Argument parsing runs on every start, including `cortex --version` and every headless call in a script, and the `cortex-cli` crate relinks on every change.

## Options considered and measured

Desktop pinned to 4 cores; sizes are a stripped release binary of a minimal program, minus an empty program ([measurements/dependency-costs.md](../measurements/dependency-costs.md)).

| Option | Dev build | Release build | Size added | Crates | Notes |
|---|---|---|---|---|---|
| **clap** with derive | 1.6 s | 4.7 s | 308 KB | 18 | Help, completions and error messages for free. A procedural macro in the crate that rebuilds most often. |
| **lexopt** | 0.3 s | 1.6 s (the empty program's own time) | 18 KB | 2 | A lexer for arguments. We write the matching, the help text and the errors. |
| Hand-rolled over `std::env::args_os` | 0 | 0 | 0 | 0 | Easy to get wrong for `--flag=value`, combined short flags, `--`, and non-UTF-8 arguments on both OSes. |

**Start-up.** A minimal program that parses a few flags and exits takes 0.36 ms with clap and 0.34 ms with lexopt, against 0.34 ms for an empty program (hyperfine, 200 runs each). That difference is inside the noise. Start-up does not separate them; build time and size do.

## Decision

lexopt, in `cortex-cli` only. Help text is written by hand and snapshot-tested. Shell completions are generated by an `xtask` command from one table that also drives the help.

## Why

- The difference is small in absolute terms, and it is paid in the places this project watches most: the relink loop of the top crate and the size budget.
- The command line is small and stable enough that a table and a match are less code than they sound.
- Hand-written help can say exactly what we want, in plain language.

## What is given up

- Derive convenience and automatic "did you mean" suggestions. Suggestions for subcommands are a few lines over the same table.

## Revisit when

The command line grows to the point where hand-written parsing is a source of bugs.
