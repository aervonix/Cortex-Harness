| **A confined command can change a file's mode and times anywhere the user owns, outside the write roots.** Landlock does not govern `chmod`, `utimensat` and their kin, and seccomp cannot check their path argument, so the sandbox cannot keep a confined command from changing the mode or the times of any file the user owns — outside the workspace too — though it cannot change the file's content there. The owner and the extended-attribute setters are refused outright, because builds do not need them (measured for cargo, git, npm, pip and make; [decision 0032](../decisions/0032-what-the-linux-sandbox-needs.md)); `chmod` and the time calls are left, because cargo, git checkouts and installers set modes and times, and refusing them would break every build. **What it costs:** a confined command can make a script outside the workspace executable (a form of deciding what runs later), set `~/.ssh/authorized_keys` to `0777` so that sshd refuses logins, make a private key readable by other local users on a shared machine, or backdate a file. It is tampering and integrity, not a content write or, with the network off, exfiltration. Found by the third review of step 26. **Recommendation:** close it when Landlock gains a metadata right (it has none through ABI 9), or when a path-aware mechanism (a BPF LSM, or a seccomp-notify supervisor that resolves the path) can refuse these calls outside the write roots without refusing them inside. Also not yet filtered: the per-directory-fd extended-attribute calls `setxattrat`/`removexattrat` (Linux 6.13), which libc does not expose portably and which glibc does not use. | Step 32 (hardening pass) | Before the first release |
