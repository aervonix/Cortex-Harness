| **Files that decide what runs later and that the protected list does not name.** The list is by name ([architecture/06-permissions-and-sandbox.md](../architecture/06-permissions-and-sandbox.md), "Protected paths"), so neither the engine nor the look after a sandboxed command protects a file that git's own configuration points to inside the workspace: a hooks directory set by `core.hooksPath` (`.githooks`, `.husky` aside, which is listed), a program named by `core.fsmonitor`, `diff.external` or a filter, or a file an `include.path` or `includeIf` reads. A confined command can rewrite such a file unseen, and it runs outside the sandbox at the user's next git command. The same holds for protected names inside a `sandbox.write` root outside the workspace, which the walk does not visit. Found by the independent review of step 26. **Recommendation:** read the repository's configuration (as git would, without running it) when a session starts and after a change to it, and add what it names inside the workspace to the watched list and to the engine's protected paths; walk the `sandbox.write` roots as the workspace is walked. | Step 32 (hardening pass) | Before the first release |
