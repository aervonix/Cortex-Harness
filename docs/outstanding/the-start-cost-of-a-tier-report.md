| **What the start cost of a tier report cannot see** ([testing-and-ci.md](../testing-and-ci.md), "Budgets are enforced"). The report takes off every test the time that 1% of the run's unit and integration tests were quicker than. Two things follow, found by the review of the change that made it. **A cost every test process shares is taken off with it:** a larger test binary that loads more slowly, a global initialiser, a heavier test harness. The start cost rises with it and the budget does not see it; the report prints the start cost, so a person can, and no check does. In the runs of 2026-11-13 it was 5 ms on Linux and 6 to 11 ms on Windows, and the quickest test of the larger integration binaries took 3 ms more than that. **A run of a few crates measures its own start,** which may be real work: the report says so below 500 tests, and changes no figure. Options: a warning when the start cost passes a ceiling (about 8 ms on Linux and 15 ms on Windows), or a start cost per binary taken from a test that does nothing. | A later tooling step | When a start cost above 12 ms is seen, or a budget is next questioned |
