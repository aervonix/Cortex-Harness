| **`shutdown` does not wait for a session that is still being put together.** Since the fixes to the review of step 13a no session starts once a shutdown has begun: one being put together when it began ends itself when its own operation reaches the core's table, and answers `shutting_down`. But `Core::shutdown` returns before that, and a process that exits then never gives that session its end: nothing is lost for a new session (it has no log until its first prompt), and a thread asking a shell its version that it started is not waited for, so the version is asked again next time. Waiting would need `shutdown` to count the sessions being put together and wait for each, which deadlocks a caller that drives every operation from one task (a test that polls by hand, or a front end that awaits each operation in turn). The recommendation is to leave it, and to have the RPC server (step 27), which runs each request as a task of its own, finish its requests before it shuts the core down.
