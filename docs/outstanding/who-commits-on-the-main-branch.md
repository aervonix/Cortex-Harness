| **Who commits on the main branch.** Pull requests are merged on GitHub by rebase (`gh pr merge --rebase`), which writes each commit again with the merging GitHub account as its committer: that account's name and email are in the metadata of every commit on the main branch, though the author is the repository's identity. The owner guard ([testing-and-ci.md](../testing-and-ci.md), "The owner guard") looks at committers, on a push to the main branch as on a pull request, so `OWNER_TERMS` holding that account's name or email fails the `ci` run of every merge; leaving them out leaves the metadata unchecked. Options: merge so that the repository's identity is the committer (a fast-forward of the main branch to the pull request's own commits, which GitHub's merge button does not do, so a push that rule "never push to main" would have to allow for this one purpose); keep rebase merges with the account set to keep its email private (GitHub then writes its `users.noreply.github.com` address, which still carries the account's name), and leave the account's name and that address out of the terms; or have the guard pass over GitHub's own committing on a push to the main branch. The existing history is not rewritten by any of these. | The owner | Before `OWNER_TERMS` is set |
