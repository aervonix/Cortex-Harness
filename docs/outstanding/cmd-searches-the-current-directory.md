| **`cmd.exe` runs a program from the directory a command runs in before it looks at `PATH`.** The shell tool keeps only the absolute entries of `PATH`, so that a file in the workspace is not found as a command, and with `cmd.exe` that does not hold: a `git.bat` the model wrote runs as `git`. A `cmd.exe` line is never analysed, so it is always asked about, and what is at stake is a command that does something other than it reads. Setting `NoDefaultCurrentDirectoryInExePath` in every command's environment turns the search off, for `cmd.exe` and for what it starts, and then a project's own batch files that call each other by bare name stop working. The recommendation is to leave it as it is and say so, which is what step 13a did. | The owner | Before the first release |
